# 2026-10-16 JST - Keep the all-normal switch cost of the priority run queue, task [#699](https://github.com/fahchen/pbeam/issues/699), pull request [#706](https://github.com/fahchen/pbeam/pull/706) - Landed

Task #699 adds the ERTS priority queues to the scheduler. The first version, `d4a8452d`, kept the `schedule_count` of each process in each entry of the shared `normal` and `low` queue, so each entry grew from 8 to 16 bytes and each pop decremented a count. That made a run with only `normal` processes slower at each switch. The change `6945485f` keeps the count of each queued `low` process in a map beside the queue. A `normal` process has the count 1, so it needs no entry, and a queue with no `low` process takes its head after three empty checks. The switch cost is then the same as on `origin/main`. The change adds no cost to the instructions between switches.

One interleaved session on 2026-10-16 measures release builds of the three revisions with 15 rounds each, in reversed order in each other round. Each round runs `pbeam yield_bench run -- yield_bench.beam` and measures the wall time of the command.

| Shape | `origin/main` `85f21026` | Count in each entry `d4a8452d` | Count map `6945485f` | Change of `6945485f` |
| --- | --- | --- | --- | --- |
| `yield_bench:run/0`, 4 processes, 400000 `erlang:yield/0` each, 1.6M switches, wall ms, median of 15 rounds | 438.3 | 445.6 | 435.9 | -0.5 percent, inside the noise |
| The same rounds, minimum | 437.1 | 443.2 | 435.4 | -0.4 percent |

The probe module is not a committed fixture:

```erlang
-module(yield_bench).
-export([run/0, worker/2]).

run() ->
    Parent = self(),
    [spawn(?MODULE, worker, [Parent, 400000]) || _ <- [1, 2, 3, 4]],
    wait(4).

wait(0) -> ok;
wait(N) -> receive done -> wait(N - 1) end.

worker(Parent, 0) -> Parent ! done;
worker(Parent, N) -> erlang:yield(), worker(Parent, N - 1).
```

Commands: `erlc yield_bench.erl`, then `CARGO_TARGET_DIR=<dir> cargo build --release --bin pbeam` for each revision, and `<dir>/release/pbeam yield_bench run -- yield_bench.beam` for each round.

## Decision

Land `6945485f`. The count map keeps the all-normal switch cost of `origin/main`, and the run order of the priority probe of `tests/integration/priority.rs` does not change.

## Known gaps

- The session measures only a switch-bound shape. The change touches only the run queue, so a shape with fewer switches for each instruction changes less. The session does not measure the dispatch floor loops or the Terra key press.
- A pop is O(1) when the shared queue has no `low` process. With `low` processes, a pop rotates each `low` head to the end of the queue at most 7 times before it runs, as `check_requeue_process` does, so a pop is O(N) in the worst case and O(1) amortized over the turns.
