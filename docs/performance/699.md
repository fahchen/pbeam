# 2026-10-16 JST - Keep the all-normal switch cost of the priority run queue, task [#699](https://github.com/fahchen/pbeam/issues/699), pull request [#706](https://github.com/fahchen/pbeam/pull/706)

Task #699 adds the ERTS priority queues to the scheduler. The first version, `d4a8452d`, kept the `schedule_count` of each process in each entry of the shared `normal` and `low` queue, so each entry grew from 8 to 16 bytes and each pop decremented a count. That adds a count write at each push and a decrement at each pop, also in a run with only `normal` processes. The change `6945485f` keeps the count of each queued `low` process in a map beside the queue. A `normal` process has the count 1, so it needs no entry, and a queue with no `low` process takes its head after three empty checks. The all-normal path then does the work of `origin/main` plus three empty checks. The change adds no cost to the instructions between switches.

## Measurement

The first session on 2026-10-16 ran release builds of `origin/main` `85f21026`, `d4a8452d`, and `6945485f`, with 15 rounds each, in reversed order in each other round. Each round ran `pbeam yield_bench run -- yield_bench.beam` and measured the wall time of the command. The medians were 438.3, 445.6, and 435.9 ms. That session did not record the one-minute load of each round, kept no raw file of each round, and gave no spread. Thus it does not obey the rules of `docs/performance-status.md`, and this record makes no claim from its numbers.

A second session was to interleave release builds of `origin/main` `ba489eb2`, `d4a8452d`, and the head `9d845fee`, with 15 rounds each. Before each run, the harness waited until the one-minute load was below 12, no `cargo`, `rustc`, or `nextest` process ran, and no `erl` or `beam.smp` process ran that was not there at the session start. The harness checked the host each 60 seconds from 07:35:50 to 08:05:54 JST. The host was never quiet in these 30 minutes: the one-minute load went from 1.3 to 29.05, and each of the 31 checks found from 1 to 10 `cargo`, `rustc`, or `nextest` processes of other sessions. Thus the session ran no round, and no raw file and no spread exist.

The decision below therefore comes from the structure of the change, not from a measured number.

The probe module is not a committed fixture:

```erlang
-module(yield_bench).
-export([run/0, worker/2]).

run() ->
    Parent = self(),
    [spawn(?MODULE, worker, [Parent, 400000]) || _ <- [1, 2, 3, 4]],
    wait(4).

wait(0) -> ok;
wait(N) -> receive done -> wait(N - 1) end.

worker(Parent, 0) -> Parent ! done;
worker(Parent, N) -> erlang:yield(), worker(Parent, N - 1).
```

Commands: `erlc yield_bench.erl`, then `CARGO_TARGET_DIR=<dir> cargo build --release --bin pbeam` for each revision, and `<dir>/release/pbeam yield_bench run -- yield_bench.beam` for each round. The harness of the second session wrote its checks to `session.log` in the session scratch directory.

## Decision

Land the count map of `6945485f`. The argument is structural. On a path with only `normal` processes, a `push` adds one 8-byte entry to the shared queue and writes no count, and a `pop` checks the empty `max` and `high` queues and the empty count map, and then takes the head. That is the work of the `VecDeque` of `origin/main` plus three empty checks, with no count for each entry and no decrement for each pop. The change adds no cost to the instructions between switches. The run order of the priority probe of `tests/integration/priority.rs` does not change. A measured claim needs a new interleaved session on a quiet host.

## Known gaps

- No session measured the change under the rules. The first session measured only a switch-bound shape. The change touches only the run queue, so a shape with fewer switches for each instruction changes less. The session does not measure the dispatch floor loops or the Terra key press.
- A pop is O(1) when the shared queue has no `low` process. With `low` processes, a pop rotates each `low` head to the end of the queue at most 7 times before it runs, as `check_requeue_process` does, so a pop is O(N) in the worst case and O(1) amortized over the turns.
