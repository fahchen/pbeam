# ERTS Differences

PBeam follows the ERTS implementation model and observable behavior. This file lists each intentional difference from ERTS and OTP. Add a row in the same PR that adds a difference. Remove the row in the same PR that removes the difference.

| Area | PBeam behavior | ERTS behavior | Reason |
| --- | --- | --- | --- |
| Scheduling | One scheduler thread. A process runs until it waits or exits. There are no reductions and no preemption. | Many scheduler threads. Each process gets a reduction budget and yields when the budget is used. | The process runtime (#49) needs only cooperative processes for OTP IO. |
| Exit signals | An abnormal exit that reaches a linked process without `trap_exit` returns a runtime error. | The exit signal kills the linked process, and the signal propagates to its links. | Exit signal propagation is not necessary for the current fixtures. |
| Receive timeout | `receive ... after` is not supported. The `wait_timeout` instruction is not decoded. | `wait_timeout` starts a timer. The process continues at the `timeout` label when the timer expires. | The current fixtures do not use a receive timeout, and PBeam has no timers. |
| Heap limit | There is no `max_heap_size` process flag and no heap accounting. | `max_heap_size` can stop a process when its heap gets too large. Messages count toward the heap only when `message_queue_data` is `on_heap`. | PBeam uses Rust memory management, not a per-process heap. |
| Process and reference counters | Process identifiers and references come from `u64` counters. Counter overflow returns a runtime error. | The number of live processes is limited by `+P` (default 1048576). Process table slots are used again. | A `u64` counter does not overflow in practice. |
| BIF instruction exception | An exception from a BIF called through `bif0`, or through `bif1` with fail label 0, returns a runtime error. A `bif1` with another fail label does not run: it returns the runtime error `unsupported BEAM opcode 10`. | The BIF raises the exception in the calling process. With a fail label that is not 0, a failure jumps to the label. | No BIF that a `bif` instruction calls on the current fixture paths raises an exception: `self/0`, `node/0`, and `node/1` with a pid always succeed. (#74) |
| Local call to a BIF stub | A local call from a module to its own function whose export is a BIF runs the BEAM body of that function. For example, a local call from `erts_internal:term_to_string/1` to `term_to_string/2` runs the stub body. Only an external call goes to the BIF. | The loader replaces the body of each function whose export is a BIF (`ops.tab`, `emu_load.c`). A local call also runs the BIF: `erts_internal:term_to_string/1` returns `"{a,1}"` for `{a,1}`. | No function on the current fixture paths makes a local call to a BIF stub. (#74) |
| Node of a term | `erlang:node/1` accepts only a pid and returns `nonode@nohost`. Any other argument returns a runtime error. | `node/1` returns the node of a pid, a port, or a reference, and raises `badarg` for other terms. Without distribution the node is `nonode@nohost`. | Only `io:io_request/2` calls `node/1` on the current fixture paths, with a pid. (#74) |
| Exception stack trace | PBeam gives each `error` exception the stack trace `[]`: in the uncaught exit reason `{Reason, []}` and in the catch value `{'EXIT', {Reason, []}}`. | ERTS records the frames, the BIF arguments, and the `error_info` location. The stack trace of `erlang:nif_error/1` starts with the `erlang:nif_error/1` frame. | PBeam records no stack frames yet. `build_stacktrace` and `raise` are not implemented yet. (#73) |
| Exception raise sites | Only `erlang:nif_error/1` and `erlang:exit/1` raise an exception that `try` and `catch` can catch. Each of these sites returns a runtime error instead: the `raise` instruction (a `try` that rethrows an exception of a class that no clause matches, and the cleanup of `try ... after`), `badmatch`, `case_end`, `if_end`, `badrecord`, `function_clause` (`func_info`), `undef` for an external function that is not loaded, `badmap` in `put_map_assoc` and in `maps:keys/1`, `badarg` in `group_leader/2` for a process that does not exist, and calls to `erlang:error/1,2` and `erlang:throw/1`. A module that contains `try_case_end` does not load. The `throw` class is not implemented. | Each site raises an exception in the calling process. `raise` raises the original class again, and the other sites raise class `error` with the reason `{badmatch, V}`, `{case_clause, V}`, `if_clause`, `{badrecord, V}`, `function_clause`, `undef`, `{badmap, M}`, `badarg`, or `{try_clause, V}`. `erlang:throw/1` raises class `throw`. `try` and `catch` can catch each of them. | Task #73 adds the exception model and the raises of `erlang:nif_error/1` and `erlang:exit/1` only. |
| Error report | PBeam writes no report for an uncaught exception. | ERTS logs `Error in process <pid> with exit value: ...` for an uncaught `error` exception (and for an uncaught `throw` as `nocatch`), but not for class `exit`. Under `erl -noshell`, the report goes to stdout. | PBeam has no logger output path yet. (#73) |
| Initial group leader | The first process is its own group leader, as the ERTS `init` process is. No `user` process exists. | A process started by `erl -eval` has the registered `user` process as its group leader. | Starting the OTP standard IO servers is not implemented yet; task #79 owns it. (#72) |
| Map keys | A map key must be an integer or an atom. A hashmap (more than 32 keys) accepts atoms and integers in the ERTS small-integer range, -(2^59) to 2^59 - 1. A BEAM map literal loads an integer key only in 0..255 (`SMALL_INTEGER_EXT`). `INTEGER_EXT` and bignum literals are not supported yet. Each unsupported case returns a runtime error. | A map accepts any term as a key. A hashmap hashes a bignum or compound term with `make_internal_hash`. | PBeam has no ERTS hash for bignums or compound terms yet. The current fixtures use integer and atom keys only. (#75) |
| Atom table | The atom table starts with the 1150 static atoms, then holds the atoms of each module in load order. PBeam does not create the atoms of emulator start and OTP boot. `BeamProgram::load` loads all modules at the start, in the given order. A literal that PBeam cannot decode yet does not create its atoms after the unsupported part. Thus an atom that is not static can get a different index than on ERTS. This changes the hashmap order of non-static atom keys, and the flatmap order of two atom keys that ERTS creates in a different order. | At `-eval` time the table holds about 10966 atoms on macOS and 10342 on Linux. The atoms from index 1150 depend on the platform and the build. After about index 3740 their order changes from run to run. In interactive mode a module loads at its first call. | PBeam does not run the emulator start or the OTP boot, and it has no code loading on demand. Even ERTS has no stable index for these atoms. (#84) |
