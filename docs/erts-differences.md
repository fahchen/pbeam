# ERTS Differences

PBeam follows the ERTS implementation model and observable behavior. This file lists each intentional difference from ERTS and OTP. Add a row in the same PR that adds a difference. Remove the row in the same PR that removes the difference.

| Area | PBeam behavior | ERTS behavior | Reason |
| --- | --- | --- | --- |
| Scheduling | One scheduler thread. A process runs until it waits or exits. There are no reductions and no preemption. | Many scheduler threads. Each process gets a reduction budget and yields when the budget is used. | The process runtime (#49) needs only cooperative processes for OTP IO. |
| Exit signals | `erlang:exit/2` sends an exit signal to a local pid as ERTS does, and a reference gives `true` with no signal. An abnormal exit that reaches a linked process without `trap_exit` returns a runtime error. | The exit signal kills the linked process, and the signal propagates to its links. | Task #135 adds `erlang:exit/2`. Link exit propagation is not necessary for the current fixtures. |
| Signal queue | A process has no signal queue. Links, unlinks, exits, monitors, demonitors, and group-leader changes take effect at once, and `EXIT` and `DOWN` go straight into the mailbox as messages. `erts_internal:group_leader/2` never returns `false`, so the `erts_internal:group_leader/3` reply path does not run. `erlang:process_info/2` reads another process at once. | Every message and control signal reaches a process through one incoming signal queue (`erl_proc_sig_queue.c`), ordered for each sender and receiver pair. The receiver handles control signals before message matching; they never enter the mailbox. A control reply comes back as a message with a fresh reference and is received selectively. `process_info/2` sends a process-info signal and waits for the reply when the other process is busy or exiting (`erl_bif_info.c:1387-1397`). | One scheduler thread cannot show the difference. #10 adds the signal queue, because two scheduler threads make signal order and handling time observable. |
| Receive timeout | A `wait_timeout` instruction with the timeout `infinity` waits as `wait` does. A `wait_timeout` with the timeout `0` or another value returns the runtime error `unsupported receive timeout`. A `receive ... after 0` with a literal `0` compiles to `timeout` without `wait_timeout`, and it runs. | With `0`, `wait_timeout` continues at once at the next instruction, `timeout`. With a finite timeout, it starts a timer, and the process continues at the next instruction when the timer expires. With `infinity`, it waits for a message without a timer. A value that is not a valid timeout raises `timeout_value` (`msg_instrs.tab`). | PBeam has no timers. `gen_statem:loop/3` waits with the `hibernate_after` option, which is `infinity` by default. (#76) |
| Heap limit | There is no `max_heap_size` process flag and no heap accounting. | `max_heap_size` can stop a process when its heap gets too large. Messages count toward the heap only when `message_queue_data` is `on_heap`. | PBeam uses Rust memory management, not a per-process heap. |
| Process and reference counters | Process identifiers and references come from `u64` counters. Counter overflow returns a runtime error. | The number of live processes is limited by `+P` (default 1048576). Process table slots are used again. | A `u64` counter does not overflow in practice. |
| Term order | The `is_lt` and `is_ge` instructions and the BIF `erlang:'>='/2` compare two terms in the ERTS term order, and `put_map_exact` sorts its keys in the ERTS flatmap key order. When the result depends on the order of two different references, `is_lt`, `is_ge`, `erlang:'>='/2`, and `put_map_exact` return the runtime error `unsupported term order of two references`. | ERTS orders two references by the reference counter of the scheduler thread that made each one, then by the thread number (`erts_set_ref_numbers` in `erl_bif_unique.h`, `ref_common` in `erts_cmp_compound` in `utils.c`). Thus a reference that a process on scheduler 1 makes later can be less than a reference that a process on scheduler 2 made earlier. | PBeam has one scheduler and one reference counter, so it cannot give the ERTS order of two references. No current fixture path compares two references. (#77, #110) |
| Integer range | PBeam stores an integer as a 64-bit signed value. `erlang:'+'/2` and `erlang:'-'/2` with a result outside -(2^63) to 2^63 - 1 return a runtime error. Integers from 2^59 to 2^63 - 1, and from -(2^63) to -(2^59) - 1, give the same results as in ERTS. An instruction operand outside the 64-bit range, such as `{integer,18446744073709551616}` in `gc_bif` or `is_lt`, loads. The instruction returns the runtime error `unsupported BEAM integer operand outside the 64-bit range: needs a bignum` when it reads the operand. | An integer outside the small-integer range -(2^59) to 2^59 - 1 is a bignum. `erlang:'+'/2` and `erlang:'-'/2` make a bignum when the result is not a small integer (`erl_arith.c:378-384`, `erl_arith.c:591-597`). The loader adds an integer operand outside this range to the literal area as a bignum (`marshal_integer` in `beam_file.c:2132-2214`). For example, `net:shortest_matching_prefix/3` has the operand 2^128 - 1 in `bsl` (`net.erl:865`). | PBeam has no bignum term yet. No integer on the measured start path of #79 leaves the 64-bit range. (#110) |
| Chardata conversion | `unicode:characters_to_binary/2` supports only the `unicode` and `utf8` encodings. It converts a binary or a proper list of integers, binaries, and nested lists. Any other encoding returns a runtime error. A code point that is not a Unicode scalar value, a run of adjacent binaries that is not valid UTF-8, and a term that is not chardata each return a runtime error. A valid binary gives an equal copy of the binary. | The BIF converts `latin1`, `unicode`, and `utf8` in C, and `unicode:characters_to_binary_int/2` converts the other encodings. Invalid input gives `{error, Converted, Rest}`, an incomplete UTF-8 sequence at the end gives `{incomplete, Converted, Rest}`, and a term that is not chardata raises `badarg`. A valid binary, or a list with only one valid binary, gives the same binary. A list can have a binary as its tail. | On the current fixture paths, `io:io_request/2` calls the BIF with `unicode`, and `group:putc_request/3` calls it with `utf8`, each with valid chardata. PBeam has no improper lists yet. (#74, #77) |
| Local call to a BIF stub | A local call from a module to its own function whose export is a BIF runs the BEAM body of that function. For example, a local call from `erts_internal:term_to_string/1` to `term_to_string/2` runs the stub body. Only `call_ext`, `apply`, `apply_last`, the `bif` instructions, a `call_fun` or `call_fun2` of an external fun, and the calls of `erlang:apply/2` and `erlang:apply/3` go to the BIF. | The loader replaces the body of each function whose export is a BIF (`ops.tab`, `emu_load.c`). A local call also runs the BIF: `erts_internal:term_to_string/1` returns `"{a,1}"` for `{a,1}`. | No function on the current fixture paths makes a local call to a BIF stub. (#74, #76) |
| Spawn of a BIF | A process that `spawn/3`, `spawn_link/3`, or `spawn_opt/4` starts with a BIF as its MFA runs the BEAM stub body of that function when its module is loaded. When the module is not loaded, the spawn returns the runtime error `unresolved external MFA`. For example, `spawn_monitor(maps, keys, [not_a_map])`, which calls `spawn_opt/4` in `erlang.beam`, runs the `maps` stub, or fails when `maps` is not loaded. A process that starts at `erlang:apply/2` or `erlang:apply/3`, as `erlang:spawn/1` makes, runs its body in `erlang.beam`, which runs the `i_apply_fun` or `i_apply` instruction, as in ERTS. | The new process calls the export of the MFA, and the export of a BIF goes to the BIF (`emu_load.c`). `spawn_monitor(maps, keys, [not_a_map])` gives the `DOWN` reason `{{badmap, not_a_map}, [{maps, keys, [not_a_map], ...}]}`. | No process on the current fixture paths starts with a BIF as its MFA. (#74) |
| Node of a term | `erlang:node/1` accepts only a pid and returns `nonode@nohost`. Any other argument returns a runtime error. | `node/1` returns the node of a pid, a port, or a reference, and raises `badarg` for other terms. Without distribution the node is `nonode@nohost`. | Only `io:io_request/2` calls `node/1` on the current fixture paths, with a pid. (#74) |
| BIF arguments | `erlang:'++'/2` with a list that is not empty on the left and a term that is not a list on the right returns a runtime error. With a pid and a valid item, `erlang:process_info/2` returns `undefined` for a process that is not alive, the item `registered_name` of each live process, and the item `current_stacktrace` of the calling process. For a live process, a list of items, the item `{dictionary, Key}`, and each other item return a runtime error. | `[1] ++ x` returns the improper list `[1\|x]`. `lists:keyfind/3` also accepts an improper list: it returns a tuple that it finds before the improper tail, and it raises `badarg` when it finds no tuple. `lists:member/2` also accepts an improper list: it returns `true` when it finds the element before the improper tail, and it raises `badarg` when it does not find the element. `process_info/2` also returns the other items, accepts a list of items for a live process, and returns `current_stacktrace` of another process (`process_info_bif` in `erl_bif_info.c`). | PBeam has no improper lists yet. On the `gen_statem` enter-loop path, `process_info/2` gets `self()` and `current_stacktrace`. On the group path, `group:server_name/0` gets `self()` and `registered_name`. The `prim_tty` writer gets the pid of its parent and `registered_name` (`prim_tty.erl:569-571`). (#76, #77, #108) |
| Exception stack trace | PBeam gives each `error` exception the stack trace `[]`: in the uncaught exit reason `{Reason, []}` and in the catch value `{'EXIT', {Reason, []}}`. `erlang:process_info(self(), current_stacktrace)` returns `{current_stacktrace, []}`, and `current_stacktrace` of another live process returns a runtime error. Thus `gen_statem:terminate/7` gets the stack trace `[]` and stops the server with `erlang:Class(Reason)` through `apply_last`, not with `erlang:raise/3`. The exit reason is the same. | ERTS records the frames, the BIF arguments, and the `error_info` location. The stack trace of `erlang:nif_error/1` starts with the `erlang:nif_error/1` frame. `process_info(self(), current_stacktrace)` returns the frames of the caller, so `gen_statem:terminate/7` runs `erlang:raise(Class, Reason, Stacktrace)`. `current_stacktrace` of another process returns the frames of that process. | PBeam records no stack frames yet. `build_stacktrace` and `raise` are not implemented yet. No start-path code reads `current_stacktrace` of another process. (#73, #76, #108) |
| Exception raise sites | Only `erlang:nif_error/1`, `erlang:exit/1`, `erlang:error/3`, and the `badarg` exceptions of `erlang:'++'/2`, `lists:keyfind/3`, `erlang:element/2`, `erlang:tuple_size/1`, `erlang:register/2`, `erlang:whereis/1`, `lists:member/2`, `erlang:process_info/2`, `erlang:iolist_to_iovec/1`, `erlang:function_exported/3`, `erlang:tl/1`, `erlang:length/1`, `erlang:atom_to_list/1`, `erlang:list_to_atom/1`, `ets:new/2`, `ets:insert/2`, `ets:lookup_element/4`, `re:compile/2`, `prim_tty:isatty/1`, `prim_tty:tty_create/1`, `prim_tty:tty_init/2`, `prim_tty:tty_window_size/1`, `prim_tty:tty_select/2`, `prim_tty:write_nif/2`, `os:set_signal/2`, `erlang:exit/2`, and the `apply`, `apply_last`, `send`, and `i_load_nif` instructions, the `badarg` and `system_limit` exceptions of `erlang:apply/2` and `erlang:apply/3`, the `system_limit` exception of `erlang:list_to_atom/1`, the `badfun` and `badarity` exceptions of the `call_fun` and `call_fun2` instructions and of `erlang:apply/2`, the `badarg` exceptions of `erlang:is_function/2` and `erlang:make_fun/3`, the `badarith` exceptions of `erlang:'+'/2` and `erlang:'-'/2`, the `badmap` and `badkey` exceptions of `erlang:map_get/2` and the `put_map_exact` instruction, and the `badmap` exception of `maps:merge/2`, raise an exception that `try` and `catch` can catch. Each of these sites returns a runtime error instead: the `raise` instruction (a `try` that rethrows an exception of a class that no clause matches, and the cleanup of `try ... after`), `badmatch`, `case_end`, `try_case_end`, `if_end`, `badrecord`, `function_clause` (`func_info`), `undef` for an external function or an external fun whose function is not loaded, `badmap` in `put_map_assoc` and in `maps:keys/1`, and calls to `erlang:error/1,2` and `erlang:throw/1`. The `throw` class is not implemented. | Each site raises an exception in the calling process. `raise` raises the original class again, and the other sites raise class `error` with the reason `{badmatch, V}`, `{case_clause, V}`, `if_clause`, `{badrecord, V}`, `function_clause`, `undef`, `{badmap, M}`, `{badkey, K}`, `badarg`, or `{try_clause, V}`. `erlang:error/3` raises class `error` with its first argument as the reason. `erlang:throw/1` raises class `throw`. `try` and `catch` can catch each of them. | Task #73 adds the exception model and the raises of `erlang:nif_error/1` and `erlang:exit/1`. Task #76 adds the `badarg` raises of the BIFs and the `apply` instructions on the `gen_statem` enter-loop path. Task #77 adds the `badarg` raises of `erlang:tuple_size/1`, `erlang:register/2`, `lists:member/2`, and `erlang:process_info/2`. Task #78 adds the `badarg` raise of `erlang:iolist_to_iovec/1`. Task #63 adds the raise of `erlang:error/3`. Task #108 adds the `badarg` raise of `erlang:whereis/1`. Task #109 adds the `badarg` and `system_limit` raises of `erlang:apply/2` and `erlang:apply/3`, the `badfun` and `badarity` raises of `call_fun`, `call_fun2`, and `erlang:apply/2`, and the `badarg` raises of `erlang:is_function/2` and `erlang:make_fun/3`. Task #110 adds the `badarith` raises of `erlang:'+'/2` and `erlang:'-'/2`. Task #111 adds the `badarg` raises of `erlang:tl/1`, `erlang:length/1`, `erlang:atom_to_list/1`, and `erlang:list_to_atom/1`, the `system_limit` raise of `erlang:list_to_atom/1`, the `badmap` and `badkey` raises of `erlang:map_get/2` and `put_map_exact`, and the `badmap` raise of `maps:merge/2`. Task #112 adds the `badarg` raises of `ets:new/2`, `ets:insert/2`, and `ets:lookup_element/4`. Task #113 adds the `badarg` raise of `re:compile/2`. Task #125 adds the `badarg` raise of the `send` instruction. Task #126 adds the `badarg` raises of `prim_tty:isatty/1`, `prim_tty:tty_create/1`, `prim_tty:tty_init/2`, and `prim_tty:tty_window_size/1`, and keeps the `badarg` raise of `prim_tty:write_nif/2` (#63) for a term that is not a TTY resource. Task #127 adds the `badarg` raise of the `i_load_nif` instruction for a file name that ERTS does not accept. Task #115 adds the `badarg` raises of `prim_tty:tty_select/2` and `os:set_signal/2`. Task #134 adds the `badarg` raise of `prim_tty:write_nif/2` for an iovec that is not a list of binaries. Task #135 adds the `badarg` raise of `erlang:exit/2`. |
| Process names | `erlang:register/2` gives a name to a process, and an exit frees the name. `erlang:whereis/1` returns the pid of a name or `undefined`, and raises `badarg` for a term that is not an atom. PBeam has no ports, so a name never gives a port. `erlang:unregister/1` and `erlang:registered/0` return the runtime error `unresolved external MFA`. The `send` instruction gives a message to the process of a registered name and raises `badarg` for a name that no process has. | `whereis/1` returns the pid or port of a name or `undefined`, `unregister/1` frees a name, and `registered/0` returns all names. A send to a registered name delivers the message, and a send to a name that is not registered raises `badarg`. | The current fixtures register names, look up names, read `registered_name`, send messages to names, and free a name with an exit only. | ETS tables | `ets:new/2` makes only `set` tables. It accepts each option that ERTS accepts, and it raises `badarg` for each call that raises `badarg` on ERTS. After these checks, the final type `bag`, `duplicate_bag`, or `ordered_set` returns a runtime error, also for `[bag, set]`. A heir that is a live process other than the caller returns a runtime error. A heir that is not alive or that is the caller acts as `none`, as in ERTS at the owner exit. `ets:insert/2` and `ets:lookup_element/4` work on `set` tables with the ERTS access rules, and they raise `badarg` as ERTS does. The key position and the index keep only their low 32 bits, as in ERTS. When the key position becomes 0, `ets:insert/2` with a tuple returns a runtime error. When the index becomes 0, `ets:lookup_element/4` for a found key returns a runtime error. An exit of the owner deletes its tables and frees their names before the name unregister, the links, and the monitors of the exit. Each other `ets` BIF, for example `ets:lookup_element/3`, `ets:info/2`, and `ets:delete/1`, returns the runtime error `unresolved external MFA`. | `ets:new/2` also makes `bag`, `duplicate_bag`, and `ordered_set` tables (`erl_db.c:2555-2840`). When the owner exits, a heir that is alive gets the table and an `ETS-TRANSFER` message (`give_away_to_heir`, `erl_db.c:5076-5080`), and a heir that is the owner changes nothing. The key position 0 aborts the emulator on an insert (status 134, `Invalid tag in make_internal_hash`), and the index 0 for a found key gives a segmentation fault (status 139) on ERTS 29.1.1. The other `ets` BIFs read, change, and delete tables. | The start path of #79 reads the application environment from `ac_tab`, a `set` table (`application_controller.erl:544-545`). No start-path code makes another table type or gives a heir. A heir that is the caller needs no table transfer, and no `ets` BIF of PBeam reads the heir. PBeam cannot copy an emulator crash. Each other `ets` BIF comes with its first consumer. (#112) |
| Regular expressions | `re:compile/2` compiles with the PCRE2 10.47 sources of OTP 29.1.1 and returns the ERTS results, messages, and offsets. It raises `badarg` for each call that raises `badarg` on ERTS, but the exception has no `error_info` cause `badopt`. PBeam keeps each compiled code until the end of the run. The compile stack guard stops at 10 KiB above the stack limit of the calling thread, as in ERTS, so the nesting depth of the error "parentheses are too deeply nested (stack check)" depends on the thread stack and the C build. With `unicode`, a pattern that is not a binary and not valid chardata, for example `foo`, returns the runtime error of `unicode:characters_to_binary/2`. Each other `re` BIF, for example `re:run/3` and `re:compile/1`, returns the runtime error `unresolved external MFA`. | ERTS keeps the compiled code in a magic binary and frees it when no term refers to it (`erl_bif_re.c:117-125`). An option error raises `badarg` with the `error_info` cause `badopt` (`erl_bif_re.c:908-912`). The stack check fails at 1687 nested `(?=` groups with the default scheduler stack and at 358 with `+sss 32`. With `+sss 256`, the first error is "regular expression is too complicated" at 1965 groups. With `unicode`, `re:ucompile/2` catches the `badarg` of `unicode:characters_to_binary/2` and raises `badarg` again (`re.erl:1742-1751`). | The start path of #79 compiles the ANSI regular expression of `prim_tty:init/1` (`prim_tty.erl:238`). PBeam has no garbage collection of resources. PBeam does not model the `error_info` of an exception (row "Exception stack trace"). The scheduler stack of ERTS and the Rust thread stack have different sizes. PBeam has no `badarg` for chardata that is not valid (row "Chardata conversion"), and it runs no `erlang:raise/3`. Each other `re` BIF comes with its first consumer. (#113) |
| Spawn options | `erlang:spawn_opt/4` accepts only the options `link` and `monitor`. Any other option returns a runtime error. A spawn with the `monitor` option returns `{Pid, Reference}`. | `spawn_opt/4` also accepts `{monitor, Options}`, `priority`, `fullsweep_after`, `min_heap_size`, `min_bin_vheap_size`, `max_heap_size`, `message_queue_data`, and `async_dist`. An option that is not valid raises `badarg`. | Only `erlang:spawn_monitor/3` calls `spawn_opt/4` on the current fixture paths, with `[monitor]`. (#87) |
| Instruction calls | An external call to `erlang:apply/2` or `erlang:apply/3` runs as the ERTS `i_apply_fun` or `i_apply` instruction. A `call_ext`, `call_ext_last`, or `call_ext_only` of `erlang:load_nif/2` runs as the ERTS `i_load_nif` instruction (see "NIF stubs"). An external call to `erlang:yield/0` or `erlang:hibernate/0` returns the runtime error `unsupported instruction call`. The `apply` and `apply_last` instructions call the function through the same path as `call_ext`, so an `apply` of `erlang:apply/2` or `erlang:apply/3` runs that apply, and an `apply` of `erlang:yield/0` or `erlang:hibernate/0` returns this error. | The loader turns these calls into the `i_apply_fun`, `i_apply`, `i_load_nif`, `i_yield`, and `i_hibernate` instructions (`ops.tab`). For `erlang:load_nif/2`, only the `call_ext`, `call_ext_last`, and `call_ext_only` forms change (`jit/arm/ops.tab:615-623`, `emu/ops.tab:854-862`). They call the function, let other processes run, or hibernate the process. `apply` and `apply_last` with `erlang:apply/2` or `erlang:apply/3` run that apply (`fixed_apply` in `beam_common.c`). | No current fixture path calls `erlang:yield/0` or `erlang:hibernate/0`. | NIF stubs | PBeam loads no NIF library. It links `prim_tty:isatty/1`, `prim_tty:tty_create/1`, `prim_tty:tty_init/2`, `prim_tty:tty_select/2`, `prim_tty:tty_window_size/1`, `prim_tty:tty_encoding/1`, `prim_tty:setlocale/1`, `prim_tty:setupterm_nif/0`, and `prim_tty:write_nif/2` as native bindings that are active when the module loads, and each entry to one of these functions runs its binding in place of the BEAM stub. `isatty/1` gives the ERTS result for fd 0, 1, or 2 of the host. `tty_create/1` keeps a TTY resource with the output fd and its first mode by reference in the typed resources of the node, next to the compiled code of `re:compile/2` (#113). PBeam keeps each TTY resource until the end of the run. `tty_init/2` gives the ERTS result and sets the ERTS raw or first mode on the output fd. It monitors the caller, and when the caller exits while it is still the owner of the resource, PBeam sets fd 0 to the first mode of the resource, as `tty_monitor_down` does (prim_tty_nif.c:1235-1241). `tty_select/2` raises `error:badarg` for a term that is not a TTY resource. Else it monitors the caller as `tty_init/2` does and returns `ok`, but it does not select fd 0 and does not read its second argument (see "Input select"). `tty_encoding/1` gives `utf8` for each term, as ERTS does on Unix (prim_tty_nif.c:287-297). `tty_window_size/1` gives the ERTS result for the window size of fd 0 or of the output fd. `setlocale/1` sets the `LC_CTYPE` locale from the environment and gives the ERTS result for its codeset. `setupterm_nif/0` reads the terminfo entry with the host curses library that the pinned ERTS links (`libncurses` on macOS, `libtinfo.so.6` on Linux), and a failure gives `{error, {setupterm, Errno}}` with the ERTS `erl_errno_id` atom. `write_nif/2` raises `error:badarg` for a term that is not a TTY resource. Else it writes each group of 1024 elements of the iovec to the output fd with `writev`, calls `writev` again on `EINTR` and `EAGAIN`, writes the remaining bytes after a partial write, and gives `{error, Errno}` with the ERTS `erl_errno_id` atom for a failed write, as ERTS does (prim_tty_nif.c:354-427). It raises `error:badarg` for an iovec that is not a list, or for a group with an element that is not a binary, after it writes the earlier groups. ERTS runs `write_nif/2` on a dirty IO scheduler (prim_tty_nif.c:161), but PBeam has one scheduler thread, so a `writev` that blocks stops all PBeam processes until it returns (see "Scheduling"). A call to each other function in `-nifs` runs its BEAM stub body. The bindings are active from module load, also before `erlang:load_nif/2` and after a failed load. A `call_ext`, `call_ext_last`, or `call_ext_only` of `erlang:load_nif/2` runs as the `i_load_nif` instruction. PBeam models each module with bindings as an ERTS static NIF library, and only `prim_tty` has bindings. It raises `error:badarg` for a file name that ERTS does not accept, with the ERTS file name encoding of the host. From `prim_tty`, it then gives the ERTS `reload`, `Function not found`, and `Function not declared as nif` errors in the order of the 20 `nif_funcs` entries (prim_tty_nif.c:153-174), else `ok`. From each other module, also an ERTS static NIF module such as `prim_file`, `prim_buffer`, `zlib`, `zstd`, `erl_tracer`, `prim_socket`, or `prim_net`, it returns a runtime error that names the module. An `apply`, `apply_last`, `erlang:apply/2`, `erlang:apply/3`, or fun call of `erlang:load_nif/2` runs the BIF, which returns the ERTS `bad_lib` error and does not check the file name. | `erlang:load_nif/2` loads the NIF library, and each NIF replaces the stub body of its function only after a successful load (`erl_nif.c:4990-5007`). ERTS uses its built-in library for a static NIF module and opens each other library with `dlopen`, which gives `{error, {load_failed, Text}}` with host text when the file does not exist (`erl_nif.c:4751-4787`).
